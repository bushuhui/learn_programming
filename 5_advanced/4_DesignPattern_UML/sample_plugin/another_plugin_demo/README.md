### Plugin 设计

如果一个工程包含很多的模块，有很多种类的插件，这种每次定义一种插件类型的方式就会变比较琐碎。

我们提供了一个demo解决这个问题

编译请执行

```bash
mkdir build
cd build
cmake ..
make
./plugin_test
```

我们需要做的仅仅是包含头文件`Avar.h`，在设计一种插件时，直接设计好接口即可，在定义插件时通过宏定义`REGISTER_PLUGIN(PluaginBase, Plugin, PluginName)`自动注册插件管理器与插件，在使用时，直接调用`Plugin(PluginBase)::create("PluginA")`



好处：插件管理与插件设计分离开来，插件自动分开管理，减少工作量

坏处：需要包含通用头文件`Avar.h`

### 扩展
正如大家所想的，插件将在dynamic library完成链接时进行注册。但是编译器为了保证代码的效率，往往在调用某个动态库的某个方法时才进行链接。结合插件的触发原理和方式，显然在实例化某个动态库的插件时可能存在插件并未注册的情况。我们可以有许多种方式解决这个问题，目前暂时使用dlopen的LAZY模式手动链接和注册插件。
另外需要考虑的一点在于单例模式在不同平台下的表现。例如许多源文件包含同一个头文件，他们被编译成不同的动态库，该单例是否拥有跨文件的特性？
